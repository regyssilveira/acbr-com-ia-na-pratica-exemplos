# Revisão de escopo — entrada guiada

## Premissa conferida

A entrega deve economizar tempo no desenvolvimento Delphi com componentes ACBr sem esconder incerteza, inventar API, tomar decisão fiscal ou executar efeito externo.

## Resultado

| Critério | Avaliação |
|---|---|
| reduz atrito para começar | sim: uma entrada coordena ferramentas existentes |
| exige evidência local | sim: projeto, paths e revisão são observados antes do prompt |
| preserva controle humano | sim: prontidão distingue autorização e ambiente externo |
| aumenta o livro | impacto mínimo: apenas um quadro de uso |
| aumenta o catálogo de skills | não: permanece com 22 |
| duplica procedimentos | não: o comando delega aos scripts existentes |
| cria risco operacional | baixo: somente leitura ou escrita em pasta nova |

## Limite adotado

Não acrescentar novos modos, dashboards ou componentes nesta edição sem feedback do piloto. A próxima expansão deve partir de falha observada por leitores, não de cobertura nominal.
